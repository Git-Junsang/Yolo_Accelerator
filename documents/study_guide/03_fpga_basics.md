[1~2장](01_cnn_basics.md)에서 "무엇을 계산하는가"(합성곱, 양자화)를 배웠다면, 이 장은 "어디서 계산하는가" — **FPGA라는 하드웨어**의 기본 부품을 소개합니다. FPGA의 자원을 알아야 [11장](11_hardware_overview.md)의 "144-MAC을 DSP48로", "버퍼를 BRAM으로" 같은 설계 결정이 이해됩니다.

## 3.1 FPGA란 무엇인가

**FPGA(Field-Programmable Gate Array)** 는 "회로를 나중에 바꿀 수 있는 칩"입니다. CPU·ASIC과 비교하면 위치가 분명해집니다.

| | CPU | **FPGA** | ASIC |
|---|-----|----------|------|
| 무엇 | 정해진 명령을 순서대로 실행 | **원하는 회로를 직접 구성** | 한 가지 회로로 고정 제작 |
| 유연성 | 소프트웨어로 자유 | 회로를 재구성 가능 | 불가 (제작 후 고정) |
| 속도/효율 | 보통 | 높음 (전용 회로) | 최고 |
| 개발 비용 | 낮음 | 중간 | 매우 높음 |

💡 **비유**: CPU가 "만능 일꾼 한 명이 작업 목록을 차례로 처리"하는 것이라면, FPGA는 "내가 원하는 모양의 조립 라인을 레고로 직접 짜서, 여러 작업을 동시에 흘려보내는" 것입니다. 신경망처럼 같은 연산(MAC)을 엄청나게 반복하는 일은, 전용 조립 라인(FPGA)이 만능 일꾼(CPU)보다 훨씬 빠르고 효율적입니다.

FPGA 안에는 수많은 작은 부품이 격자처럼 깔려 있고, 우리는 그것들을 **연결하는 방법(설정)** 을 정의합니다. 그 정의를 Verilog 같은 언어로 쓴 것이 RTL이고, 그것을 부품 연결 정보로 바꾸는 과정이 "합성/구현"입니다([3.6](#36-rtl에서-비트스트림까지)).

---

## 3.2 기본 부품 ① — LUT와 플립플롭(FF)

FPGA의 가장 기본 부품 두 가지입니다.

### LUT (Look-Up Table) — 조합 논리

LUT는 "입력 조합에 대한 출력을 적어둔 작은 표"입니다. 어떤 논리식이든(AND, OR, 복잡한 if문) 이 표로 흉내 낼 수 있습니다.

```
4-입력 LUT 예: 출력 = (a AND b) OR (c XOR d)
입력 abcd → 출력을 표에 미리 저장 → 입력이 오면 표에서 찾아 출력
```

### 플립플롭(FF) — 기억(레지스터)

FF는 "클럭이 똑딱일 때마다 값을 한 개 저장하는 칸"입니다. Verilog의 `reg`가 보통 FF가 됩니다. **순차 논리(시간에 따라 값이 바뀜)** 의 기본입니다.

```verilog
always @(posedge clk)   // 클럭 상승 에지마다
    count <= count + 1; // count를 FF에 저장 (1씩 증가)
```

💡 **비유**: LUT는 "계산기"(입력 넣으면 즉시 답), FF는 "메모지"(클럭 똑딱마다 한 값을 적어둠)입니다. 회로는 계산기로 계산하고 메모지에 기록하기를 반복합니다.

---

## 3.3 기본 부품 ② — DSP48 (곱셈기)

LUT로도 곱셈을 만들 수 있지만 매우 비효율적입니다. 그래서 FPGA에는 **곱셈 전용 블록 DSP48**이 따로 박혀 있습니다.

- DSP48 하나는 큰 곱셈(예: 18비트 × 25비트)과 덧셈을 빠르게 합니다.
- 이 프로젝트의 INT8 × INT8 곱셈은 DSP48 하나로 충분합니다.
- Artix-7 XC7A100T에는 DSP48이 **240개** 있습니다.

> 🔑 **이 프로젝트는 DSP48을 144개 사용**합니다([11장](11_hardware_overview.md)의 144-MAC). 240개 중 144개니까 여유가 있습니다. 곱셈을 LUT로 만들면 240개로는 어림없으니, DSP48을 쓰는 것이 필수입니다. [14장 mul.v](14_rtl_convolution_engine.md)는 합성 시 `xbip_dsp48_macro_0`이라는 DSP48 IP를 직접 인스턴스화합니다.

⚠️ **"곱셈은 비싸다"는 감각**: 하드웨어에서 곱셈기는 덧셈기보다 훨씬 크고 전력을 많이 씁니다. 그래서 "곱셈기 개수(=144)"가 이 설계의 핵심 제약이자 성능 지표가 됩니다. 반대로 나눗셈은 더 비싸서, [2장](02_quantization_basics.md)에서 본 것처럼 나눗셈을 시프트로 대체합니다.

---

## 3.4 기본 부품 ③ — BRAM (블록 메모리)

FPGA 안의 **작지만 빠른 메모리**입니다. FF로도 메모리를 만들 수 있지만, 수천~수만 칸이 필요하면 FF는 너무 낭비라 BRAM을 씁니다.

- BRAM 한 블록은 보통 36Kbit. Artix-7 XC7A100T에는 약 135개(≈4.86Mbit).
- **데이터 폭과 깊이를 설정**해서 다양한 모양으로 씁니다(예: 128비트 × 2048칸, 32비트 × 65536칸).
- Xilinx에서는 **BMG(Block Memory Generator)** IP로 BRAM을 만듭니다([21장](21_vivado_project.md)).

### BRAM의 가장 중요한 성질 — read latency

> 🔑 **BRAM은 "주소를 주면 그 다음 클럭에 데이터가 나옵니다"** (read latency = 1 cycle). 즉시 나오지 않습니다.

```
클럭 0: 주소 A 입력
클럭 1: 데이터[A] 출력  ← 1 클럭 늦게!
```

이 1클럭 지연이 [4장](04_rtl_timing_basics.md)에서 자세히 다룰 "타이밍 정렬"의 근원입니다. 여러 BRAM의 지연을 어긋나지 않게 맞추는 것이 이 설계에서 가장 까다로운 부분입니다.

💡 **비유**: BRAM은 "도서관 사서에게 책 번호를 말하면, 잠시 후(1클럭) 책을 가져다주는" 것과 같습니다. 말하자마자 책이 손에 있는 게 아닙니다.

이 프로젝트는 BRAM을 ① 가중치 버퍼 ② 입력 라인 버퍼 ③ 출력 버퍼로 씁니다([11·15장](15_rtl_memory_buffers.md)). 외부의 큰 데이터는 DRAM(보드의 DDR2)에 두고, 자주 쓰는 것만 BRAM에 올려 빠르게 접근합니다.

### BRAM vs DRAM

| | BRAM (온칩) | DRAM (보드의 DDR2) |
|---|------------|---------------------|
| 위치 | FPGA 칩 안 | 칩 밖 |
| 크기 | 작음 (~수백 KB) | 큼 (수 MB~) |
| 속도 | 빠름 (1클럭) | 느림 (여러 클럭 + 버스 거침) |
| 전력 | 낮음 | **높음** |

> 🔑 **DRAM 접근은 가장 큰 에너지원**입니다. 그래서 이 설계는 "한 번 읽은 데이터를 BRAM에 두고 최대한 재사용"하여 DRAM 접근을 줄입니다(streaming weight, in-place pool 등 — [18장](18_operation_timing.md)). 이것이 Energy 점수를 올리는 핵심입니다.

## 3.5 면적·속도·전력의 트레이드오프

FPGA 설계는 세 가지를 저울질합니다.

- **면적(area)**: LUT/FF/DSP/BRAM을 얼마나 쓰는가. 칩 용량 안에 들어가야 함.
- **속도(clock frequency)**: 클럭을 얼마나 빠르게 돌릴 수 있는가(MHz). 빠를수록 추론이 빠름(fps↑).
- **전력(power)**: 얼마나 전기를 쓰는가. 점수의 Energy 항.

이들은 서로 얽혀 있습니다. 예를 들어 곱셈기를 144개에서 288개로 늘리면 더 빠르겠지만(속도↑) 면적·전력이 늘고 DSP가 부족할 수 있습니다. 이 프로젝트가 **144개로 고정**한 것은 이 균형점입니다([11장](11_hardware_overview.md)).

## 3.6 RTL에서 비트스트림까지

우리가 쓴 Verilog가 실제 FPGA에서 동작하기까지의 과정입니다([21장](21_vivado_project.md)에서 실제 명령으로).

```mermaid
graph LR
    RTL["Verilog RTL<br/>(.v 파일)"] --> SYN["합성 Synthesis<br/>논리 → 부품(LUT/FF/DSP)"]
    SYN --> IMPL["구현 Implementation<br/>부품 배치 + 배선"]
    IMPL --> BIT["비트스트림 .bit<br/>(FPGA 설정 파일)"]
    BIT --> FPGA["FPGA에 적재<br/>→ 회로 동작"]
```

1. **합성(Synthesis)**: Verilog를 LUT·FF·DSP·BRAM 같은 실제 부품의 연결로 변환.
2. **구현(Implementation)**: 그 부품들을 칩의 실제 위치에 배치하고 전선으로 연결(place & route).
3. **비트스트림 생성**: FPGA를 설정할 `.bit` 파일 생성.
4. **적재**: `.bit`를 FPGA에 다운로드하면 우리가 설계한 회로가 칩 안에 만들어집니다.

이 프로젝트는 합성/구현/시뮬레이션을 **Vivado**(Xilinx 도구)로 합니다([8·21장](21_vivado_project.md)).

> 🔑 **시뮬레이션 vs 합성**: 실제 칩에 올리기 전에, RTL이 올바른지 PC에서 **시뮬레이션**으로 검증합니다([19장](19_testbench_strategy.md)). 시뮬레이션에서는 DSP48·BRAM 대신 그것을 흉내 내는 "behavioral 모델"을 씁니다. 이 전환이 [4장](04_rtl_timing_basics.md)·[21장](21_vivado_project.md)의 `` `define FPGA `` 매크로입니다.

## 3.7 타이밍 클로저 (Timing Closure)

FPGA가 특정 클럭(예: 100MHz = 10ns 주기)으로 동작하려면, **모든 조합 논리가 한 클럭 주기 안에 계산을 끝내야** 합니다. LUT·전선을 거치는 데 시간이 걸리므로, 너무 복잡한 논리를 한 클럭에 몰면 제때 못 끝냅니다.

```
클럭 주기(10ns) 안에:  FF → LUT들 → FF  계산이 완료되어야 함
  완료 못 하면 → 타이밍 위반(timing violation) → 동작 보장 불가
```

해결책은 **파이프라인**(긴 계산을 여러 클럭으로 쪼갬 — [4장](04_rtl_timing_basics.md))입니다. 모든 경로가 시간 안에 들어오면 "타이밍 클로저를 달성했다"고 합니다. 이 프로젝트의 최종 클럭 주파수는 구현 후 확정되며, [18장](18_operation_timing.md)의 fps 추정에 영향을 줍니다.

## 3.8 이 프로젝트의 FPGA — Artix-7 XC7A100T

| 자원 | 양 | 이 프로젝트 사용 |
|------|----|------------------|
| 로직 셀 (LUT/FF) | ~101,440 | FSM·제어·정렬 논리 |
| DSP48 | **240개** | 144개 (144-MAC) |
| Block RAM | ~135개 (4.86Mbit) | 가중치·라인·출력 버퍼 |
| 외부 메모리 | DDR2 (보드) | 가중치·IFM·OFM 저장 |

Digilent **Nexys A7-100T** 보드에 이 칩이 올라가 있고, UART(USB)로 PC와 통신합니다. DSP는 여유롭고, **BRAM 용량과 DDR2 대역폭이 주요 제약**입니다.

## 3.9 이 장의 요약

- FPGA는 "회로를 직접 구성하는 칩". 같은 연산을 대량 반복하는 신경망에 CPU보다 효율적.
- 기본 부품: **LUT**(조합 논리·계산), **FF**(기억·레지스터), **DSP48**(곱셈 전용, 240개 중 144개 사용), **BRAM**(빠른 온칩 메모리).
- **BRAM은 read latency 1클럭** — 주소를 주면 다음 클럭에 데이터. 이 지연 정렬이 설계의 핵심 난점([4장](04_rtl_timing_basics.md)).
- DRAM 접근은 가장 큰 에너지원 → BRAM 재사용으로 줄이는 것이 Energy 점수의 핵심.
- RTL → 합성 → 구현 → 비트스트림. 시뮬레이션은 behavioral 모델로(매크로 전환).
- 타겟: Artix-7 XC7A100T (DSP 240, BRAM ~135), Nexys A7-100T 보드.

다음 장에서는 이 부품들로 정확히 동작하는 회로를 만들기 위한 **RTL 설계와 타이밍**을 배웁니다.
